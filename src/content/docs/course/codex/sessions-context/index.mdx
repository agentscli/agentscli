A **session** is a saved conversation you can reopen with `codex resume`. While it runs, Codex carries one **context window**: everything in the transcript, file bodies it has read, tool output, standing instructions, and tool definitions. The window has a fixed capacity (often discussed as on the order of 200k tokens in current models). Nothing in it empties by itself on ordinary turns - read a file and the window only grows. (Near the capacity limit Codex may compact automatically; [the compact lesson](/course/codex/sessions-context/compact/) covers that escape valve and why you should usually compact on purpose instead.) Talk for an hour and the spare room shrinks. Resume yesterday and yesterday's transcript rides into today.

That is the local problem this chapter addresses. **Context** (what the agent can see when it decides) is paid per session, not per repo. A small codebase can still fill a window if the conversation is long, forked, or full of repeated reads. Each command here trades window space against continuity on purpose: reopen understanding, split threads, shed weight in place, read the gauge, or start clean.

## What each lesson covers

| You need to… | Lesson |
| --- | --- |
| Pick up a saved conversation across days | [Resume](/course/codex/sessions-context/resume/) (`codex resume`, `/resume`, `--last`, scoped picker) |

| Answer a disposable question without polluting the main transcript | [Side](/course/codex/sessions-context/side/) (`/side`) |
| Keep the same task but reclaim window room | [Compact](/course/codex/sessions-context/compact/) (`/compact`) |
| See how full the window is before you spend more | [Status](/course/codex/sessions-context/status/) (`/status`) |
| Move to unrelated work without dragging old context | [Reset](/course/codex/sessions-context/reset/) (fresh `codex`, `/new`, `/clear`) |

One distinction runs through several lessons: **resuming restores the conversation, not the working tree.** Files on disk are whatever `git status` and your tests say now; the transcript is a record of what was said when. Put durable facts in commits, notes, or [`AGENTS.md`](/foundations/rules/) so they load in every session regardless of which thread you open.

## Example repo

Where a concrete tree helps, lessons use **budgetcli**: a small self-hosted personal-finance API, 166 lines of Python and about 230 lines including tests, config, rules, and README, with a pytest suite and an `AGENTS.md` at the repo root. Each page restates the files and facts it needs; you do not need prior chapters to follow a single lesson.

Start anywhere that matches your question, or walk forward from [resume](/course/codex/sessions-context/resume/) if you want the usual reading order.
