**No built-in plan mode.** There's no toggle that flips Pi into a read-only, plan-then-execute posture the way Claude Code's Shift-Tab or OpenCode's `plan` primary agent do.

**Ways to get the same discipline:**
- **Write the plan to a file** and ask Pi to draft it before touching code — plain prompting, no special mode required. This is the zero-setup option and works today.
- **Install or build a plan-mode extension.** The Pi repo's `examples/extensions/` directory includes a plan-mode example demonstrating the pattern via the ExtensionAPI — intercept edit/bash calls, require a written plan first, then lift the gate.
- **Ask Pi to build one for you.** Since extensions are just code Pi can write, describing the plan-mode behavior you want and having the agent implement it as a project extension is a legitimate path, consistent with Pi's overall "build it from primitives" philosophy.

If plan mode is a hard requirement for your workflow, it's worth weighing against the effort of assembling the equivalent yourself.
