**Configuration:** hooks live in `settings.json` (project, user, or managed levels). All registered hooks merge - Claude Code fires every loaded hook that matches a given event. `--bare` and other configuration choices can prevent project hooks from being discovered.

**Events:** `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `SessionStart`, `Stop`, `SubagentStop`, `PreCompact`, `Notification`, and more.

**Hook actions** can be:
- A shell command
- An HTTP request
- A prompt sent to Claude
- A subagent invocation
- An MCP tool as the hook handler (`type: "mcp_tool"`). To *match* Claude's own MCP tool calls in `PreToolUse` / `PostToolUse`, use a matcher like `mcp__<server>__<tool>` - `mcp_tool` is the handler type, not the matcher.

**Example** (`.claude/settings.json`):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "scripts/check-bash-command.sh"
          }
        ]
      }
    ]
  }
}
```

Hook output can land in the conversation as a message - a `PostToolUse` hook running your linter feeds errors back to Claude as text it can read and act on.
