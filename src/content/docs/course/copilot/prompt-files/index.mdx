title: "Prompt files & slash commands"
description: "A repeated multi-step request can be frozen into a prompt file you invoke with a slash command. Deprecated in favor of Agent Skills, but still worth understanding."
---

[Rules](/course/copilot/rules/) handle one kind of repetition: the standing conventions otherwise re-typed into every chat. There is a second kind rules cannot touch. Not "match the house style" - that is standing context and it is handled - but the *specific procedure* you spell out from scratch every time: scaffold an endpoint our way, with the route, the validation call, the audit event, the threshold check, the test. Five steps, the same five steps, phrased slightly differently each time and occasionally missing one because you typed it from memory.

That is exactly what a **prompt file** is for: a reusable, named prompt saved in the repo and invoked on demand with a slash command. The instruction lives in a file, version-controlled and shared with your team, so "scaffold an endpoint our way" stops being something you reconstruct each time and becomes one command everyone runs the same way.

:::caution[Deprecated - migrate to Agent Skills]
Two engine names to pin down: **Agent Host** is the current default agent experience in VS Code; the **Local agent** is the older engine, which still loads prompt files but is scheduled for removal ([VS Code prompt files documentation](https://code.visualstudio.com/docs/agent-customization/prompt-files), verified September 2026). Prompt files are deprecated for Agent Host sessions, and Agent Host does not load them at all: on the default experience, a prompt file's slash command will not appear. VS Code provides prompt file migration to convert existing prompts to Agent Skills. Treat this chapter as still accurate on the mechanics, usable where the Local agent is active, and a migration source - the [create lesson](/course/copilot/prompt-files/create/) includes a quick empirical check for which engine you are on. The [Skills chapter](/course/copilot/skills/) covers the durable destination.
:::

The distinction at the heart of the chapter is *always-on* versus *on-demand*. Rules apply automatically, every request, whether or not you are thinking about them. Prompt files run only when you call them - and skills, taught in the Skills chapter, are invoked by the model itself when the task matches. Getting a feel for which repeated work belongs in which container is the judgment this chapter builds.
