OpenCode's hook model is **plugin-based**. You write a JS/TS plugin module that exports a hook map, and OpenCode wires the hooks in.

A plugin is a named async export. It receives a context object (`project`, `client`, `$`, `directory`, `worktree`) and returns an object of hook handlers:

```ts
export const LintOnEdit = async ({ project, client, $ }) => ({
  event: async ({ event }) => {
    if (event.type === 'file.edited') {
      await $`pnpm lint ${event.properties.file}`;
    }
  },
  'tool.execute.before': async (input, output) => {
    if (input.tool === 'read' && output.args.filePath.includes('.env')) {
      throw new Error('Do not read .env files');
    }
  },
});
```

Events arrive through the `event` hook and are matched on `event.type`; interception hooks such as `tool.execute.before` / `tool.execute.after` and `shell.env` are their own keys on the returned object (a thrown error in `tool.execute.before` blocks the call).

**Available events** include `command.executed`, `file.edited`, `file.watcher.updated`, LSP events, message events, `permission.asked`, `permission.replied`, session/server events, `session.idle` and other session events, shell/tool execution events (`tool.execute.before`, `tool.execute.after`, `shell.env`), and TUI prompts/commands/notifications.

The event taxonomy is richer than Claude Code's, but you need to author a plugin to use any of it - there's no `settings.json`-style declarative hook list.
