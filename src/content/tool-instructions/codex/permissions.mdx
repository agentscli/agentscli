Codex separates **what the agent is allowed to touch** (sandbox) from **when it asks before acting** (approval policy). The two combine.

**Sandbox modes** (`--sandbox`):
- **`read-only`** - agent can read but cannot edit files or run commands
- **`workspace-write`** - agent can edit files inside the workspace and run sandboxed commands
- **`danger-full-access`** - no sandboxing (use deliberately)

**Approval policies** (`--ask-for-approval`):
- **`on-request`** - agent decides when to ask
- **`never`** - never ask

In `config.toml`, `approval_policy` also accepts a `granular` table of booleans (`sandbox_approval`, `rules`, `mcp_elicitations`, `request_permissions`, `skill_approval`) that picks which kinds of request still prompt. `untrusted` is no longer supported and `on-failure` is deprecated.

Common combinations:
- **Plan-like behaviour:** `--sandbox read-only --ask-for-approval on-request`, or switch to Plan mode with `/plan`
- **YOLO mode:** `--sandbox danger-full-access --ask-for-approval never` (only in throwaway environments)
