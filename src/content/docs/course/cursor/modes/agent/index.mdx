**Agent** is the right posture for most work, and it's the mode you'll spend the most time in. You describe an outcome; it does the whole loop - reads what it needs, edits across however many files it decides are relevant, runs tests, reads the failures, and fixes them - surfacing risky commands for approval as it goes rather than stopping to plan with you first.

Agent is the correct posture when the change is *contained* and you'd rather review a finished diff than co-author the approach. A gnarly algorithm that lives entirely in one file you own is a perfect Agent task even though it's hard - the difficulty is real but the blast radius is small, so letting it run and reviewing the result is cheaper than narrating every step.

```text
agent ›
> the retry backoff in rates/fetcher.go is linear; make it exponential
  with jitter, capped at 30s, and keep the existing max-attempts
  behaviour.

  ⏵ Read   rates/fetcher.go, rates/fetcher_test.go
  ⏵ Edit   rates/fetcher.go   → exponential backoff + jitter, 30s cap
  ⏵ Run    go test ./rates/...
    • ok  0.18s
  Done. Backoff now doubles per attempt with ±20% jitter, capped at
  30s; max-attempts unchanged. Tests pass.
```

What you're trusting Agent with is *latitude*, not correctness - you still review the diff. The judgment is matching that latitude to the stakes, which is exactly where Plan comes in. [Next: Plan, clarify and research first](/course/cursor/modes/plan/).
