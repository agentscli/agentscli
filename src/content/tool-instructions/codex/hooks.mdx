**Configuration:** Codex hooks load from either an inline `[hooks]` table in `config.toml` or a standalone `hooks.json`, at user (`~/.codex/`) and project (`.codex/`) levels. Enterprise admins can also ship managed hooks via `requirements.toml`.

**Events:** `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `Stop`, `Interrupt`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop` - twelve at the time of writing; check the current reference, since the list grows between releases.

**Hook actions:** `command` and `mcp_tool` handlers run today (the schema parses `prompt` and `agent` types but skips them). A command script receives a JSON event payload on stdin (`session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`, `permission_mode` on several events, plus a `turn_id` for turn-scoped events). Non-managed hooks must be reviewed and trusted (use `/hooks`) before they run, and project hooks load only when the project is trusted.

**Example** (`~/.codex/config.toml`):

```toml
[[hooks.PreToolUse]]
matcher = "Bash"

  [[hooks.PreToolUse.hooks]]
  type = "command"
  command = "scripts/check-bash-command.sh"
```
