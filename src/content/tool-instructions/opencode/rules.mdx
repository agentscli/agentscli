**Files OpenCode reads,** in this order:

1. **Local**, walking up from the current directory - `AGENTS.md`, then `CLAUDE.md` as a fallback
2. **User-wide** - `~/.config/opencode/AGENTS.md`
3. **Claude Code compatibility** - `~/.claude/CLAUDE.md`, unless you disable it

The first match wins *per category*, so a project with both `AGENTS.md` and `CLAUDE.md` uses only `AGENTS.md`. The two Claude Code paths are the reason OpenCode often works on a repo already set up for Claude Code without you writing anything new: point it at an existing `CLAUDE.md` and it reads it.

**Standard:** OpenCode is the other implementation of the [`agents.md` spec](https://agents.md/). A project's `AGENTS.md` is portable between OpenCode and Codex with no changes.

**Behavioral rules:** OpenCode does **not** have a separate "Rules" file - `AGENTS.md` *is* the rules layer. For additional rule sources, point at extra files via the `instructions` field in `opencode.json` (accepts file paths or glob patterns).

**Nested files:** OpenCode walks up from the current working directory and the **first matching file wins per category** - a subdirectory's `AGENTS.md` *replaces* (does not merge with) a parent's.

**`@path` imports:** Not parsed. OpenCode does not auto-resolve `@path` references inside `AGENTS.md`. Workarounds: list the files in `opencode.json`'s `instructions` field, or instruct the agent in prose to read specific files on demand.
