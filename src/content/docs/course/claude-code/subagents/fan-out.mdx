One found bug is not a clean bill of health. In the small Express plus TypeScript payments service this course uses as its example, a single [subagent](/course/claude-code/subagents/) (a worker with its own context window that returns a summary) has already traced why every balance reads zero: the route in `src/index.ts` files ledger entries under the payment's UUID, and the balance route reads by account id. Before fixing that line you want the ground around it audited, and the audit splits cleanly into four slices:

1. **Ledger writes and their coverage.** Every call to `append` in `src/payments/ledger.ts`, its callers, and which of the six green tests exercise them.
2. **Idempotency semantics.** `checkIdempotency` in `src/utils/idempotency.ts` and its caller in `src/payments/processor.ts`.
3. **The rate limiter's async path.** `allowAsync` versus the synchronous `allow()` in `src/payments/rate-limiter.ts`.
4. **The fee math.** The total computed in `src/payments/processor.ts`, checked against the rule in the repo's `CLAUDE.md`: use integer cents for all money, never floating point.

Four questions, and none of them needs another's answer. That independence is the license for a fan-out: one subagent per slice, each in a context window of its own, each reading the code as it stands, all running at the same time.

## Four audits that never touch each other

Ask for parallel subagents and Claude spawns one per slice, each in its own context window (the run shows Claude's default `general-purpose` workers):

```text
audit the payments service in parallel - one subagent per slice:

1. ledger writes: every append and its callers, and which tests
   actually cover them
2. idempotency semantics in src/utils/idempotency.ts and its caller
   in src/payments/processor.ts
3. the async path in src/payments/rate-limiter.ts versus allow()
4. the fee math in src/payments/processor.ts against the cents rule
   in CLAUDE.md

report per slice: what the code does, the defect if any, and the
evidence for it. conclusions only.
```

The run below is illustrative, not captured. The tool counts are invented; every finding is what the course's example payments repo contains:

```text
⏵ Agent (general-purpose)  ledger writes   ▶ running
⏵ Agent (general-purpose)  idempotency     ▶ running
⏵ Agent (general-purpose)  rate limiter    ▶ running
⏵ Agent (general-purpose)  fee math        ▶ running

  ⎿ ledger writes  done (12 tool uses)
  ⎿ rate limiter  done (10 tool uses)
  ⎿ idempotency   done (14 tool uses)
  ⎿ fee math      done (9 tool uses)

  Synthesized across all four:
  - Ledger: the only write is the route call that files entries under
    the payment UUID - the bug you already found. The tests cover the
    Ledger class directly; nothing covers the route.
  - Idempotency: checkIdempotency records a key on first check, so a
    payment that fails after the check still burns its key and a
    legitimate retry is rejected as a duplicate. markProcessed is
    never called; a request with no key is never deduped at all.
  - Rate limiter: allow() filters and decides in one synchronous
    step; allowAsync() snapshots the bucket before its await and
    writes back after it, so concurrent callers on a fresh key each
    check their own empty array - all pass, and the last write
    clobbers the rest. The limit admits the whole burst while the
    map undercounts.
  - Fee math: the processor computes the fee-inclusive total
    (amount * 1.029; the fee itself is amount * 0.029) in floating
    point against CLAUDE.md's integer-cents rule - and the test
    enshrines it, asserting the exact float 2056.971 and passing.
```

Four investigations ran concurrently, and each one's noise stayed in its own window: the twelve calls the ledger worker made never mixed with the limiter worker's ten, and none of it entered your thread. When they finished, Claude read the four summaries and synthesized them. This is the documented [parallel research](https://code.claude.com/docs/en/sub-agents#run-parallel-research) pattern, and its license is the sentence to hold onto: the research paths do not depend on each other.

## When parallel pays - and when it is overkill

The temptation, once the fan-out works, is to reach for it constantly. Resist. Parallelism pays when two things are both true: the slices are genuinely independent, and each is heavy enough that running them in sequence would make you wait. The audit qualifies on both counts: four separate questions, each a real dig.

It is overkill, or worse, when:

- **The slices depend on each other.** If auditing idempotency required what the ledger audit found, they could not run at the same time; you would be guessing. Chain them instead, so one subagent's result feeds the next. The docs cover this under [chaining subagents](https://code.claude.com/docs/en/sub-agents#chain-subagents).
- **The work is light.** Spawning fresh agents that each gather context from scratch can be slower than one main thread that already holds it. Fan-out has fixed startup cost; tiny tasks do not earn it back.
- **You are fanning out wide for the sake of it.** The docs carry a real warning here, and it is the sharp edge of the whole technique.

That warning is worth quoting straight, because it is the one that bites: "Running many subagents that each return detailed results can consume significant context." See [run parallel research](https://code.claude.com/docs/en/sub-agents#run-parallel-research). The reason you delegated was to keep noise out of your thread, and ten subagents each handing back a detailed report is its own flood, arriving all at once.

The fix is in the brief: ask for conclusions, not dumps. "Report the defect and the evidence," not "report everything you found." A worker that returns three lines protects your context; one that returns three pages has relocated the problem rather than solved it. So the shape that works is a handful of independent, heavy slices, each briefed to come back terse.

These four finished while you watched. A longer pass, such as the full suite, lint, build, and a fresh sweep, is the kind of job you eventually stop wanting to watch at all. [Next we push work into the background](/course/claude-code/subagents/background/) and keep going while it runs.
