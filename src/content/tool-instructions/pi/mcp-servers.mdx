**Pi has no native MCP support, and that's deliberate.** The whole design is four built-in tools — `read`, `write`, `edit`, `bash` — and everything else grows from `bash`, not from a growing list of first-class integrations. Adding an MCP client would cut against that minimalism.

**What to do instead:**
- For most integrations, a **CLI tool plus a skill or README** covering how to call it gets you the same outcome through `bash` — no protocol layer needed.
- If you specifically need MCP (e.g. to reuse an existing server you run for other tools), build or install an **extension** that adds an MCP client via the ExtensionAPI. This isn't shipped by default — check the extensions ecosystem for whether one already exists before writing your own.
- External **bridges** that translate MCP calls into shell invocations are another option if the server you need only speaks MCP.

If your workflow leans heavily on MCP servers today, this is the sharpest tradeoff to weigh before adopting Pi as your primary loop.
