Start with the simplest layer of Cursor's standing instructions, because it's the one that travels. Drop an `AGENTS.md` at the root of `budgetcli` - the course's illustrative TypeScript finance API - write down the conventions that otherwise live only in your head, and you're covered on every tool that reads the standard:

```markdown title="AGENTS.md"
# budgetcli

A budgeting / personal-finance API (TypeScript). You're working on live
transaction data - be precise about money and time.

## Conventions

- All timestamps are stored and compared in **UTC**. Parse incoming dates to
  UTC at ingest; never store server-local time.
- Every API handler validates its request body with a **Zod schema** before
  touching business logic. Do not hand-roll validation with `if` checks.
- Money is **integer cents**, never a float. Format to a currency string only
  at the response boundary, never in storage or maths.
```

There's no special syntax to learn - Cursor reads `AGENTS.md` the way the model reads any prose: headings, terse imperative bullets, the things that bite. Every line earns its place because it's something Cursor got *wrong*, not something it could read off the source. Nothing in there says "write clean code" or transcribes the directory layout; that just burns context. Write it the way you'd brief a sharp new engineer on day one.

The payoff is portability. Because this is the [`agents.md` open standard](https://agents.md/) - whose adopter list names Cursor alongside Codex, OpenCode, and others - the same file is in force whether your teammate clones `budgetcli` into Cursor, Codex, or OpenCode. One file, every tool, no per-tool translation.

Keep the portable guarantee simple: put shared project guidance in a root-level `AGENTS.md`. Nesting is supported too - Cursor's docs state that "You can place `AGENTS.md` files in any subdirectory of your project, and they will be automatically applied when working with files in that directory or its children" (as of September 2026; [rules documentation](https://cursor.com/docs/context/rules)), with nested instructions combined with the parent's and "more specific instructions taking precedence" (as of September 2026). The root file remains the default; reach for a nested one only when a subsystem genuinely needs its own scoped instructions.

:::tip[Try it]
Write three rules in `AGENTS.md` for `budgetcli`: one about money (integer cents), one about test commands (`npx vitest`), one about import style. Start a new chat and ask for a feature. Check whether the rules held.
:::

Portability is what `AGENTS.md` buys you. What it can't buy you is conditionality beyond directory nesting - rules that attach by file pattern, when the model judges them relevant, or on demand - and that's the gap Cursor's own format was built to fill.
