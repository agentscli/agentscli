**Configuration:** `mcp.json`, resolved in priority order:

1. **Project:** `<repo>/.cursor/mcp.json`
2. **User:** `~/.cursor/mcp.json` (also `~/.config/cursor/mcp.json` on Linux)

The top-level key is `mcpServers`; the schema mirrors the common MCP shape: `type`, `command`, `args`, `env`, `envFile` for stdio; `url` and `headers` for remote. Variable interpolation works in `command`, `args`, `env`, `url`, and `headers`.

**Transports:** all three are supported - **stdio** (Cursor spawns and manages a local process), **SSE** (local or remote, Server-Sent Events), and **streamable HTTP** (local or remote).

**One-click install:** Cursor has a curated **Marketplace** in-app (installed from Customize), a community directory at **cursor.directory**, and team marketplaces that admins use to distribute servers. An "Add to Cursor" button uses a deep link to write the server into the user's `mcp.json` and trigger OAuth if needed.

**OAuth:** remote servers can use Cursor's built-in OAuth flow; register the redirect URL that matches where users sign in: `http://localhost:8787/callback` for the desktop app, `https://www.cursor.com/agents/mcp/oauth/callback` for web and Cursor Agents. Static OAuth client credentials (`auth` with `CLIENT_ID`, optional `CLIENT_SECRET` and `scopes`) can be embedded in `mcp.json` when the provider requires fixed Client IDs.

There is also an **MCP Extension API** for extensions to register MCP servers programmatically - niche, but it exists.
