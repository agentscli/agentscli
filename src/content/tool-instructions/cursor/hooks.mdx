Cursor has a **Hooks** primitive. Hooks are spawned subprocesses that communicate via stdin/stdout JSON. The event set and response contract are version-sensitive; verify the exact reference for the Cursor surface you deploy. *As of 2026-08-07.*

**Config files:**

- **User:** `~/.cursor/hooks.json`
- **Project:** `<repo>/.cursor/hooks.json`
- **Enterprise / Team:** platform-managed and dashboard-distributed

**Schema:** `{"version": 1, "hooks": { "<event>": [{ "command": "..." }] }}`.

**Event surface:** the current reference documents agent, shell, MCP, file, prompt, and workspace lifecycle events. The exact event list is version-sensitive. *Unverified:* the older “21+ events” count is not a stable contract.

**Agent hooks:** `sessionStart`, `sessionEnd`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeShellExecution`, `afterShellExecution`, `beforeMCPExecution`, `afterMCPExecution`, `beforeReadFile`, `afterFileEdit`, `beforeSubmitPrompt`, `preCompact`, `stop`, `afterAgentResponse`, `afterAgentThought`.

**Tab hooks** (inline completion): `beforeTabFileRead`, `afterTabFileEdit`.

**App lifecycle:** `workspaceOpen`.

**Enforcement:** JSON output and exit codes drive policy. For permission hooks, exit `0` uses the JSON response; `permission: "deny"`, invalid JSON, or a response that does not match the schema blocks the action. Exit `2` also blocks. Other non-zero exits, crashes, timeouts, and missing output fail open by default.

For a security-critical hook, set the documented per-script option `failClosed: true`; Cursor then blocks when the hook crashes, times out, exits non-zero, or produces no output. Keep the wrapper's own error handling explicit as defense in depth, and test the allow, deny, malformed-output, timeout, and crash paths before relying on the boundary. Confirm this contract against the [current Hooks reference](https://cursor.com/docs/hooks) when upgrading Cursor. *Verified 2026-09-22.*

The combination of `beforeShellExecution`, `beforeReadFile`, and `beforeMCPExecution` covers most policy-enforcement use cases (secret scanning, command allowlists, audit logging). Claude Code can gate corresponding tool calls through `PreToolUse` matchers, although it does not give the read and MCP moments these dedicated event names; Codex has no direct equivalent hook surface.

A separate **Third-Party Hooks** doc covers reusable hook scripts.
