## The cost rule you can apply without a price tag

You don't need a number to make the right call, because the relationship is fixed regardless of what the number is:

> **More reasoning effort means more tokens generated and more latency before the answer. Always. A bigger model compounds it.**

That's true at every price point, so the discipline doesn't depend on the price - it depends on knowing the *ratio*. The question is never "what does `high` cost?" It's "**does this task's value justify the extra tokens and the wait that `high` spends?**" On the wiring - hooking `categorise()` into the import, where a wrong seam means re-doing it and miscategorizing money - yes, easily. On the filter - the pattern-following endpoint change - no: the extra reasoning produces the same three lines, more slowly, for more tokens. Same dial, opposite verdict, no dollar figure needed.

## The matched corner, run for real

Enough constructed corners. The matched cell on the fork row is this chapter's hard task, and the narrative now executes it. The prompt goes to Codex under `budget-design` - capable model, `high` effort, read-only sandbox, `on-request` approvals - and what comes back is the proposal the traces kept describing: hook in `parse_csv`, conflicts by table order, manual posts keep their sender's category.

The seam decision, once more, because it is the fork's whole content: `parse_csv` is where a description first becomes data; the import route is its only caller; the ledger stores whatever it is handed. Hooking the route instead would leave `parse_csv` returning half-labeled transactions and put taxonomy knowledge in the HTTP layer.

```python
# app/importers/csv.py - the two added lines
from app.services.categorise import categorise
...
        transactions.append(
            Transaction(
                description=row["description"],
                amount_cents=amount_cents,
                category=categorise(row["description"]),
                date=date,
            )
        )
```

Two lines: an import, and a `category=` argument in the constructor call. The conflict rule is the function's own semantics - lowercase both sides, substring match, first row of the table that hits wins. When a description contains two keywords, the earlier row wins: order *is* the priority - deterministic and auditable, which is exactly what a keyword table buys over a scoring approach.

```python
# tests/test_import.py - the two tests added
def test_parse_csv_categorises_descriptions():
    transactions = parse_csv(SAMPLE_CSV)
    assert transactions[0].category == "dining"      # Starbucks Coffee
    assert transactions[1].category == "groceries"   # Whole Foods Market
    assert transactions[2].category == "transport"   # Uber Ride

    transactions = parse_csv(

Pinned by tests, the wiring holds: an imported Starbucks row lands `dining` on every future run, and a category filter no longer returns empty for everything because nothing was ever categorized.

## What this doesn't solve

A matched verdict is not a correctness guarantee. It means the level spent roughly the right amount of effort finding an answer - you still read the diff and the proposal the way any reviewed change deserves ([the first-change lesson](/course/codex/getting-started/first-change/) covers that habit). And the dial can't diagnose the task's shape for you: treat the wiring as boilerplate, or the filter as a design problem, and you land in the wrong row of the table however carefully you read the output.

It doesn't substitute for the rules file, either. The wiring edit landed inside the very block where `app/importers/csv.py` constructs a `Transaction` - and a few lines above the new argument, the float parse still turns amount strings into cents through `int(float(...))`. Leaving it was correct, by ticket scope: the wiring didn't ask for it, and out-of-scope edits are how reviews lose trust. But matched effort enforced nothing. The parse-path rule is still a proposal in `AGENTS.md`, and the float is still live.

One more ceiling, carried over from the dial page: the level list is model-dependent - `xhigh` in particular is not available everywhere. Whether your session offers the deepest gears depends on model and auth - worth checking before you plan an afternoon around a gear you might not have.

## What recurs and what does not

Set this chapter's output beside the rules chapter's. The `AGENTS.md` audit bought understanding that recurs automatically, because a file Codex reads carries it into every session.
