[Foundations](/foundations/) explains what each primitive *is*. [Courses](/course/) teach one tool end to end. Playbooks sit between them: a named procedure for a specific, recurring problem — "how do I get an agent to build a feature from a mockup," "how do I trust an agent's fix without reading every line" — that works the same way regardless of which CLI you're driving it from.

A page here earns its place if it's a **repeatable move**, not a one-off tip: something you'd reach for by name the next time the same problem shows up, in any tool.

## Available now

- **[TDD with agents](/playbooks/tdd-with-agents/)** — write the failing test first, commit it as the spec, then let the agent close the loop against it.
- **[Design-to-code](/playbooks/design-to-code/)** — hand the agent pixels, anchor them to your real tokens and components in text, then diff the result against the source yourself.
- **[Architecture diagrams via agent](/playbooks/architecture-diagrams/)** — ask for Mermaid text, not a picture, and verify the edges against the code before you trust the map.
- **[AFK agents](/playbooks/afk-agents/)** — kick off work you won't babysit; earn the walk-away by shrinking the blast radius, not by trusting the model more.
- **[AI-ready code](/playbooks/ai-ready-code/)** — audit how a fresh agent navigates your codebase, then fix the structure — not the docs — where it fails.

Many of these moves also ship as installable [skills](/foundations/skills/): each chapter's **Off the shelf** block names verified picks, and `npx skills find` searches the cross-tool registry at [skills.sh](https://skills.sh) for more. The skill runs the procedure; the playbook is the why and the when.

More playbooks are on the way. If the one you need isn't here yet, the closest primitive is probably in [Foundations](/foundations/), or check the [course](/course/) for your tool.
