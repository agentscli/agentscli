**Subagents** are spawned via the `Agent` tool. Custom subagents live at:
- `.claude/agents/<name>.md` - project
- `~/.claude/agents/<name>.md` - user
- Plugin-bundled
- Managed-policy

**Frontmatter:**

```yaml
---
name: code-reviewer
description: Reviews a diff for bugs, performance, and security issues.
tools: [Read, Grep, Glob]      # restrict the subagent's tool surface
skills: [security-checklist]   # preload these skills into its context
---
```

**Precedence (most-wins):** managed > CLI flag > project > user > plugin.

**What the subagent inherits:** a fresh context, its own agent prompt, basic environment details, and whatever the parent passes in the prompt. Custom subagents can receive relevant project context, but the built-in Explore and Plan agents do not inherit `CLAUDE.md` or the parent's git status. It does **not** inherit the parent's conversation history. *As of 2026-08-07.*

That last point is the cost lever. A **fork** (today via `/subtask` on current versions; briefly `/fork` in the mid-2.1.x line) is the variant that reuses the parent's system prompt, tools, *and* conversation history, so its first request can hit the parent's cache and is cheaper than spawning a fresh subagent. Reach for a fork when you want the parent's exact setup, and a subagent when you want isolation.

**Agent teams (experimental)** are different - independent peer Claude Code sessions that message each other and share a task list. Use a subagent when only the result matters; use an agent team when teammates need to discuss and coordinate.
