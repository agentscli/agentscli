This is a **hands-on course**, not a reference: every lesson takes a problem you'll actually hit and shows the exact move that fixes it. If you want the spec-level "what is this primitive" view, that's [Foundations](/foundations/) - this course is the other half, the muscle memory.

## Four principles that organize everything

Claude Code has a lot of surface - models, permission modes, sessions, skills, subagents, hooks, headless runs. Underneath, four principles sort all of it, and this course returns to them by name:

- **Capability** - what the agent can figure out and accomplish with its model and tools. Picking a model, raising its reasoning effort, delegating to subagents, connecting systems through MCP: all capability decisions.
- **Context** - what information is available when the agent decides. Instructions, rules, skills, retrieved files, tool results, memory, the conversation itself. Context is the discipline this whole course teaches: what the agent sees, when, and how much you can trust it.
- **Control** - what guides execution, enforces boundaries, or lets you intervene. Permission modes and rules, plan mode, hooks, deny lists, the fail-closed posture an unattended run needs (refuse rather than guess when a check cannot run).
- **Cost** - what completing the task consumes: money and tokens, compute, elapsed time, your attention, and rework when something goes wrong.

They trade against each other. A stronger model cannot recover a fact the agent never saw (capability does not replace context); a rule in context asks the model nicely, while a permission or hook enforces (guidance is not control); an unattended run needs checks it can trust before you walk away (control buys back cost). You will meet these trades in the chapters, stated where they matter.

## How to read it

Each module is a **chapter** - not a stack of disconnected reference cards. The lessons build on each other: each one picks up a problem, adds a move to your repertoire, and hands off to the next.

Read in order and you get the full progression. Land mid-course from a search and the page still works: every lesson states its own problem, its starting facts, and the terms it uses, so no earlier chapter is required reading - just more depth when you want it.

What you won't find is a fixed template stamped onto every lesson. Some need a long worked transcript, some a single command and a warning, some a digression into *why* the tool behaves the way it does. The shape follows the content, the way a good book varies its chapters.
